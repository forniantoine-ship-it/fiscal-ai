# Dashboard Page Rules

## Page Goal

The dashboard is the central hub of the entire product experience.

It acts as:
- onboarding,
- progress tracker,
- navigation center,
- reassurance layer,
- workflow entry point.

The dashboard must immediately communicate:

"This is simple. The software is guiding me."

Users should instantly understand:
- where they are,
- what is completed,
- what remains,
- what happens next.

The dashboard must reduce anxiety and create clarity.

---

## UX Intent

The dashboard should feel:
- calm,
- lightweight,
- premium,
- extremely understandable.

This page replaces traditional onboarding flows.

Users should not feel like they are entering:
- accounting software,
- admin software,
- fiscal configuration tools.

The experience should feel closer to:
- premium consumer software,
than to professional accounting platforms.

The dashboard must always communicate:

"Upload documents. The AI prepares the declaration. You validate."

---

## Core Components

The dashboard should contain:

### 1. Hero Section

Includes:
- declaration year badge,
- reassuring headline,
- short explanatory text,
- primary CTA.

Recommended messaging:

Headline:
"Prepare your LMNP declaration simply."

Supporting text:
"Upload your documents. The AI prepares your declaration automatically. Simply review and validate before generation."

Primary CTA:
"Continue my file"

---

### 2. Global Progress Section

Display:
- overall completion percentage only.

Avoid:
- analytics,
- KPI dashboards,
- complex statistics,
- accounting summaries.

The goal is reassurance, not reporting.

---

### 3. Horizontal Workflow Navigation

Main workflow steps:
- My Activity
- Property
- Loan
- Amortization & Works
- Income
- Expenses
- Validation

Navigation must remain:
- horizontal,
- lightweight,
- persistent,
- easy to understand.

Users can:
- skip steps,
- return later,
- freely navigate.

Each step can display:
- completed,
- in progress,
- incomplete states.

States must remain visually subtle.

---

### 4. Documents Analyzed Section

This section appears near the bottom of the dashboard.

Purpose:
- reassure the user,
- create a feeling of progress,
- show AI activity,
- centralize uploaded files.

The dashboard should not become:
- a document manager,
- a file explorer,
- a backoffice.

Documents should remain visually lightweight.

Each item can display:
- document name,
- detected category,
- analysis status.

Example states:
- analyzed,
- processing,
- missing,
- incomplete.

Actions available:
- view,
- replace,
- delete.

Actions should remain discreet.

---

### 5. Save Status

Display a subtle auto-save state.

Example:
"Automatically saved"

The purpose is reassurance.

---

## Required Behaviors

The dashboard must:
- load quickly,
- feel lightweight,
- immediately orient the user,
- clearly indicate the next recommended action.

Users must feel:
- guided,
- reassured,
- free to navigate.

The dashboard should intelligently encourage:
- workflow continuation,
- missing document completion,
- declaration progression.

---

## AI Behavior

The AI should feel:
- active,
- discreet,
- useful,
- invisible.

The dashboard should communicate:
- document analysis,
- automatic extraction,
- workflow preparation,
without exposing technical complexity.

Avoid:
- AI jargon,
- technical OCR terminology,
- processing complexity.

---

## States

Important states:
- empty state,
- first connection,
- partially completed file,
- fully completed file,
- missing documents,
- processing documents.

All states must remain:
- calm,
- premium,
- reassuring.

Avoid:
- aggressive warnings,
- alarming colors,
- stressful UI patterns.

---

## Important Constraints

The dashboard must never feel:
- overloaded,
- technical,
- corporate,
- accounting-heavy.

Avoid:
- dashboard complexity,
- excessive metrics,
- large data tables,
- fintech aesthetics,
- ERP layouts.

The interface must prioritize:
- simplicity,
- whitespace,
- clarity,
- calm hierarchy,
- premium visual rhythm.

This page is the emotional entry point of the product.

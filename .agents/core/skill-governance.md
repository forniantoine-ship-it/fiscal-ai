# Skill Governance

Objectif : empêcher la prolifération incontrôlée des Skills.

## Avant de créer un nouveau Skill

Vérifier, dans cet ordre :

1. peut-on enrichir un Skill existant ?
2. existe-t-il des Skills qui devraient être fusionnés ?
3. un Skill existant est-il devenu obsolète ou redondant ?
4. seulement si aucune de ces solutions n'est adaptée : création éventuelle d'un nouveau Skill.

Un nouveau Skill ne doit être créé que s'il représente une compétence réellement distincte et réutilisable.

**Une nouvelle tâche ne justifie jamais à elle seule la création d'un Skill.**

Si un nouveau Skill provoque un chevauchement important avec un Skill existant, préférer fusion / remplacement plutôt qu'addition.

Toute création, fusion, remplacement ou suppression d'un Skill doit être justifiée dans le compte rendu de mission.

## Important — connaissance fiscale

Une nouvelle règle fiscale découverte pendant une tâche ne doit **pas** devenir automatiquement un Skill.

Elle doit d'abord être établie / validée dans la connaissance métier canonique du Knowledge System (`knowledge/`).

- Le **Skill** décrit *comment* utiliser la connaissance.
- Le **Knowledge System** contient *ce qui est considéré comme* connaissance métier canonique.

Voir [.agents/skills/README.md](../skills/README.md) pour la liste des Skills existants et [fiscal-proof-standard.md](fiscal-proof-standard.md) pour la chaîne de preuve requise avant promotion en connaissance canonique.
